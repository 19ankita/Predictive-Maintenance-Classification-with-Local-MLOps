# Predictive Maintenance Classification with Local MLOps

An end-to-end machine learning and MLOps project for predicting industrial machine failures using sensor and operational data. The project demonstrates a complete local ML lifecycle covering data validation, feature engineering, imbalanced classification, model comparison, hyperparameter optimization, experiment tracking, model registration, data drift detection, and model explainability.

## Project Overview

Predictive maintenance aims to identify potential machine failures before they occur, enabling organizations to reduce unplanned downtime, maintenance costs, and operational disruptions.

This project develops a multiclass classification system to predict different machine failure conditions from operational sensor data.

The workflow follows a production-oriented machine learning lifecycle:

```text
Raw Data
   ↓
Data Validation & Cleaning
   ↓
Feature Engineering
   ↓
Train / Validation Split
   ↓
Class Imbalance Handling (SMOTE)
   ↓
Baseline Model Training
   ↓
Model Comparison
   ↓
Hyperparameter Optimization (Optuna)
   ↓
Experiment Tracking (MLflow)
   ↓
Model Registration
   ↓
Data Drift Detection (Evidently)
   ↓
Model Explainability (SHAP)
```

## Key Objectives

* Build a robust predictive maintenance classification model

## Dataset

The project uses industrial machine operational data containing sensor and process variables such as:

* Air temperature
* Process temperature
* Rotational speed
* Torque
* Tool wear
* Machine type

The target variable represents machine failure conditions.

The failure classification problem contains multiple failure categories, making **macro-F1** particularly important for evaluating model performance because the classes are imbalanced.

## Feature Engineering

Several domain-informed features were engineered to improve predictive performance.

### Mechanical Power

Mechanical power was derived from torque and rotational speed:

```text
Power (W) = Torque × Rotational Speed × 2π / 60
```

This feature provides an estimate of the mechanical power generated by the machine.

### Temperature Difference

The difference between process and air temperature was calculated as:

```text
Temperature Difference = Process Temperature − Air Temperature
```

This captures the relative thermal load of the machine.

## Data Preprocessing

The preprocessing workflow includes:

* Data quality checks
* Data type validation
* Missing-value handling
* Feature engineering
* Encoding categorical variables
* Train-validation splitting
* Class imbalance analysis

A stratified **80/20 train-validation split** was used to preserve the class distribution.

## Handling Class Imbalance

The dataset contains highly imbalanced failure classes.

**SMOTE (Synthetic Minority Oversampling Technique)** was applied only to the training data to avoid data leakage.

```text
Original Training Data
        ↓
     SMOTE
        ↓
Balanced Training Data
        ↓
      Model
```

The validation set remained untouched and retained the original class distribution.

## Machine Learning Models

Multiple classification algorithms were evaluated:

* Logistic Regression
* Random Forest
* XGBoost
* LightGBM

The models were evaluated using:

* Accuracy
* Macro F1-score
* Weighted F1-score
* Per-class F1-score

### Why Macro F1?

Because the dataset contains rare failure categories, accuracy alone can hide poor performance on minority classes.

Macro F1 gives equal importance to each class and was therefore used as the primary model-selection metric.

## Hyperparameter Optimization

The best-performing candidate model was further optimized using **Optuna**.

The optimization workflow used:

* 30 Optuna trials
* TPE-based sampling
* Fixed random seed for reproducibility
* Macro F1 as the optimization objective

The optimized XGBoost model was subsequently registered using MLflow.

## Experiment Tracking with MLflow

MLflow was used to implement local experiment tracking and model management.

The project tracks:

* Model parameters
* Training metrics
* Validation metrics
* Macro F1
* Weighted F1
* Accuracy
* Per-class F1 scores
* Model artifacts

Two experiments were used during the workflow:

```text
PredMaint_ModelSelection
PredMaint_Optuna
```

The optimized model was registered as:

```text
PredMaint_XGBoost
```

This demonstrates reproducible experiment management and model versioning within a local MLOps environment.

## Data Drift Detection

Production-like stress data was evaluated using **Evidently** to identify changes in the input feature distributions.

The drift analysis detected changes in:

* Rotational speed
* Torque
* Tool wear

The stress batch showed drift in **3 out of 5 monitored features**.

The analysis used statistical distribution comparisons, including Wasserstein-based measures, to quantify differences between reference and current data.

This demonstrates how monitoring can identify changes in production input data that may affect model reliability.

## Model Explainability

**SHAP (SHapley Additive exPlanations)** was used to understand model predictions and identify the contribution of individual features.

SHAP analysis helps answer questions such as:

* Which features influence predictions most strongly?
* Why was a particular machine assigned to a failure class?
* Which operational variables contribute to failure predictions?

This provides greater transparency and supports model debugging and stakeholder interpretation.

## Key Technical Challenge

One of the key challenges was predicting rare machine failure categories.

The **TWF failure class** contained very few observations, resulting in an F1-score of 0.0 even after applying SMOTE and hyperparameter optimization.

This highlights an important practical limitation:

> Oversampling can improve class balance, but it cannot fully compensate for severe information scarcity in extremely rare failure categories.

For production deployment, additional failure observations, improved data collection, anomaly detection, or specialized rare-event modelling could be investigated.

